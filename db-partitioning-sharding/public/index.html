Horizontal Sharding: Naive Mod-Hash vs. Consistent Hashing

Every user below is stored on one of several independent shards (physically separate JSON "databases" under server/data/shards-*). Two strategies place the same user on a shard, side by side: naive mod-hashing (hash(id) % N) and consistent hashing with virtual nodes. Add or remove a shard and watch how many keys have to move under each strategy — this is the single biggest reason consistent hashing exists.

Range Partitioning: One Table, Many Physical Segments

Orders live in a single logical table that is physically split into monthly range partitions (server/data/partitions/orders_YYYY_MM.json) — all on the "same database", unlike sharding above. Query by date range and see partition pruning in action: only the partitions that can contain matching rows are scanned.
